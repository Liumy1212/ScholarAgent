# 文档维护规则

本文件扩展根目录 `AGENTS.md`，适用于 `docs/` 下的内容。

## 文档职责

- `architecture.md` 只记录当前已经落地的系统边界、数据流和长期有效约束。
- `roadmap.md` 记录当前阶段、契约已定义但尚未实现的能力，以及未来规划。
- `deployment.md` 记录可复制执行的环境配置、首次部署、后续运行、停止、验证和排错步骤。
- 项目概览和文档导航只放在根 `README.md`，不要在 `docs/` 新建重复索引。

## 写作规则

- 文档中文优先，命令、路径、API 字段和代码标识符保持英文。
- 不创建 ADR、决策日志或按历史决策编号的文档。
- 不跨文档复制长段说明；确定唯一来源后使用相对链接。
- 严格区分“已实现”“契约已接受”“规划中”，不得把目标设计写成当前能力。
- 代码、配置和文档不一致时先检查真实实现与验证结果，再更新现状描述。
- 删除或重命名文档时，必须检查仓库内所有 Markdown 相对链接。

## 验证

- 检查 Markdown 链接目标存在。
- 确认环境变量、版本和命令与配置及脚本一致。
- 运行受影响模块要求的检查和 `git diff --check`。
